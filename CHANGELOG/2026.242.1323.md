# 2026.242.1323 — fix: a C-style // comment made this candy unconsumable

## Summary

`charly.yml` line 115 carried a **C-style comment in a YAML file**:

```yaml
// download verb: see the pinned ACT_VERSION/ACTIONLINT_VERSION
```

YAML has no `//` comment form. The parser therefore read `// download verb` as a **key** whose value
is the string `see the pinned ACT_VERSION/ACTIONLINT_VERSION`, and CUE rejected it at a position
that requires a struct:

```
node "// download verb": #NodeDoc."// download verb": conflicting values
"see the pinned ACT_VERSION/ACTIONLINT_VERSION" and {...} (mismatched types string and struct)
```

**This is not cosmetic and not local.** It fails in *any* project that resolves this candy, so
`v2026.241.0554` — the newest published tag — cannot be composed at all. I found it while attempting
a whole-tree pin sync of `distro-cachyos` (`opencharly/distro-cachyos#41`): advancing
`layer-github-actions` to its newest tag turns that project's validation from clean into a hard
error, which is how a stale pin ends up being the only thing keeping a consumer working.

The fix is one character: `//` → `#`. The line was always meant to be a comment, and as a comment it
now is one.

**Why the other two lines move.** `charly box validate` — the gate for this change class — refuses
to run until the schema is migrated:

```
schema 2026.240.1943 is required (found "2026.232.0520"). Run: charly migrate
```

and the migration is exactly what makes the CI's pinned charly too old:

```
config schema 2026.240.1943 is newer than this charly supports
```

Landing either half alone leaves the repo broken in one direction or the other, so all three land
together.

### 3. How the defect was found, and why it matters beyond this repo

Reproduced from a *consumer*, which is where the real cost lands:

```
$ # distro-cachyos, all stale pins advanced (the sync in distro-cachyos#41)
$ charly box validate
charly: error: command "validate": 2 validation errors:
  candy "github-actions": CUE schema: …/layer-github-actions@v2026.241.0554/charly.yml:
    "// download verb": conflicting values … (mismatched types string and struct)
  candy "github.com/opencharly/layer-github-actions": …same…
```

The error surfaces twice because the candy is reached both by bare name and by pinned ref.

### 4. Why `CHARLY_PLUGIN_ONLY=1`

`plugin_loader.go:434 warnSkippedFHSPlugins()` fires when the running binary is not at
`/usr/bin`/`/usr/local/bin` while `/usr/lib/charly/plugins` holds `.providers` manifests — those
plugins belong to the installed charly **2026.187.2228**, 55 days and a schema epoch from what this
tree needs, so charly refusing them is correct behaviour rather than noise.
`plugin_loader.go:454` documents `CHARLY_PLUGIN_ONLY=1` as *"the supported way to resolve
AS-IF-UNPACKAGED"*: it drops the FHS path from the search, masking nothing, and its output is
byte-identical to the normal run minus that one line.
